# AWS Cloud Threat Detection & Incident Response Lab

## Overview

This lab demonstrates a controlled AWS cloud security monitoring and incident-response workflow using AWS-native security services.

The exercise covers:

- CloudTrail activity logging
- IAM identity investigation
- Amazon GuardDuty threat detection
- AWS Security Hub finding centralization
- Credential containment
- Persistence analysis
- Incident remediation

Implementation
1. Test IAM Identity

A dedicated IAM user named incident-response-test was created in the Dev account.

The identity received only the permissions required for controlled API activity.

2. CloudTrail

API activity generated by the test identity was observed through CloudTrail Event History.

The investigation focused on:

Identity
API action
Timestamp
Region
Source IP
User agent
3. GuardDuty

AWS-provided sample findings were generated in the Security / Log Archive account to validate the GuardDuty detection workflow.

4. Security Hub

GuardDuty sample findings were observed in Security Hub to demonstrate centralized security finding management.

5. Investigation

CloudTrail was used to investigate activity associated with the test IAM identity.

6. Credential Containment

The test access key was disabled.

Authentication using the disabled credential was then tested and failed.

7. Persistence Analysis

CloudTrail was reviewed for IAM actions that could establish persistence, including:

Access key creation
User creation
Role creation
Policy attachment
Group membership changes
Trust policy changes
8. Remediation

After evidence collection, the temporary access key and test IAM identity were removed.
