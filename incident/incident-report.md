# Incident Investigation Report

## Scenario

A controlled AWS security exercise was performed to demonstrate the investigation and containment of a potentially compromised IAM identity.

The exercise used a dedicated IAM test identity and did not involve malware or an actual attack against AWS infrastructure.

## Environment

- AWS Organization
- Security / Log Archive account
- Dev member account
- AWS IAM
- AWS CloudTrail
- Amazon GuardDuty
- AWS Security Hub

## Test Identity

`incident-response-test`

The identity was intentionally configured with limited permissions.

## Detection

CloudTrail was used to record API activity generated by the test identity.

GuardDuty sample findings were separately generated to validate the detection and Security Hub integration workflow.

> GuardDuty and Security Hub findings used in this laboratory were AWS-provided sample findings. They were not generated by an actual compromise.

## Investigation

CloudTrail was used to identify:

- IAM identity
- API actions
- Timestamp
- AWS Region
- Source IP
- User agent
- Related IAM activity

## Timeline

| Stage | Activity |
|---|---|
| 1 | Test IAM identity created |
| 2 | Limited policy attached |
| 3 | Access key created |
| 4 | Controlled API activity generated |
| 5 | CloudTrail events observed |
| 6 | GuardDuty sample findings generated |
| 7 | Security Hub finding observed |
| 8 | Test identity activity investigated |
| 9 | Access key disabled |
| 10 | Authentication failure validated |
| 11 | Persistence-related IAM activity reviewed |
| 12 | Test credentials removed |

## Containment

The test IAM user's access key was disabled.

A subsequent authentication attempt using the disabled credential failed, demonstrating successful containment.

## Persistence Analysis

CloudTrail was reviewed for IAM actions that could establish persistence, including:

- CreateAccessKey
- CreateUser
- CreateRole
- AttachUserPolicy
- AttachRolePolicy
- PutUserPolicy
- PutRolePolicy
- AddUserToGroup
- UpdateAssumeRolePolicy

No persistence activity was intentionally generated by the test identity.

## Remediation

After evidence collection and investigation:

- The test access key was deleted.
- The temporary IAM test identity was removed.
- No unnecessary test infrastructure was retained.

## Conclusion

The exercise demonstrated a controlled cloud incident-response workflow using AWS-native security services:

CloudTrail → Investigation → GuardDuty → Security Hub → Identity Investigation → Credential Containment → Persistence Review → Remediation
